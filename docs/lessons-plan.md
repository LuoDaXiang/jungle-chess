# 教学关卡改造方案

这份文档是 React 教学运行时的规格说明，不是待办清单。写在这里而不是留在对话里，
是因为对话会过去，仓库不会。

## 为什么现在只改了两步

完整方案要新增目标类型，而判定逻辑 `checkLessonGoal()` 住在 `legacy/index.html`
里——那 900 行确定要被 React 重写。在那里实现一套判定系统，等于写两遍，
而且第二遍还得对着第一遍做行为对照。这和「规则两份实现」是同一类错误。

所以只做了不需要改运行时的部分：第 2 关补两步，纯数据追加。
外加一个例外——「延时退回」，三行，但不做的话新增的那一步等于白写。

## 已经做了的

- 第 2 关第 3 步：文案改成点明「场上没子了算平手」。局面本来就是最后两子相撞，
  引擎判 `Draw`，只是以前没说。
- 第 2 关新增第 4 步：红方只剩一只狮，黑方有狮和猫。撞过去两只狮子一起没，
  红方无子而输。**黑方必须留那只猫**——只有两只狮子的话撞完是平手，
  证明不了「拿最后一子去换会输」。
- 原第 4 步（狮吃豹）语音 key 顺延为 `l2_s5`。
- 走错时先把后果留在屏幕上 850ms 再退回，期间锁输入。

## 四子迷你对局：实测数据

`cargo run --release -p jungle-ai --example mini_match`

| 孩子替身 | 平均局长 | 下不完 | 孩子胜率 |
|---|---:|---:|---:|
| 第一档（瞎逛） | 158 步 | 47% | 27% |
| 第二档（有目的） | 15 步 | 0% | 100% |

**配子没问题，成败取决于孩子会不会往兽穴走。**所以这一关必须带兜底：
若干步没有进展就提示「别忘了，走进对方的家就赢了」。不加这个，
最需要帮助的那个孩子会卡在 158 步的瞎逛里。

两个档位都不是真实六岁小孩的好替身，所以上面是区间不是定值。

## 还没做的：目标类型

现有六种（`inspect / move / capture / safeMove / den / play`）都只判「落在哪一格」，
判不了「触发了什么规则结果」。React 版需要：

- `identifyMove { rank }` —— 第 1 关：听名字选出指定动物并走一步
- `captureResult { target, mutual }` —— 区分普通吃子、同归于尽、陷阱单方面吃子。
  **读引擎返回的 `MoveOutcome`，不要在教学代码里复制等级判断。**
- `outcome { outcome }` —— 验证和棋 / 胜 / 负
- `tryIllegalThenMove { tryTo, then }` —— 必须亲手试一次的规则。
  **不能做成门禁**：孩子不试就卡死且不知道为什么。应该是邀请——
  几秒没动静就说「你试试让狼下水，看看会怎么样」，试不试都能过。
- `match { setup, winRequired }` —— 取代含义模糊的 `play`，同时支持迷你局和完整局

评审里原本还提了一个 `collision`，已并入 `captureResult`——两者都只是读
`MoveOutcome`，一个类型够用。教学运行时的类型越少，能出错的地方越少。

**好消息**：这些类型需要的 `mutual` / `captured` / `outcome` 字段，
Rust 引擎已经返回，WASM 接口已经暴露。教学判定不用复制任何规则。

## 错误处理：必须分两类

- **规则上非法**（狼下水、象吃鼠、进自己的家、被鼠挡住还想跳）→ 弹回 + 解释。
  引擎没有合法的后果局面，硬走完是在演示假规则。
- **合法但是坏棋**（进敌方陷阱、拿最后一子同归于尽）→ **走完，让孩子看见后果**，
  停一下，再复原。教学题里复原，真实对局里不复原。

## 复习

不做复习关列表，不做每日打卡，不做星级。用嵌入式复现：
第 4 关让水里鼠鼠相撞复习同归于尽，第 5 关用同级子吃陷阱里的同级子复习例外，
迷你对局再用一遍全部规则。六岁孩子需要的是重新遇见，不是被测验。
